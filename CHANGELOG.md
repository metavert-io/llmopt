# Changelog

## 2026-11-14

- **Report**: the downloadable report is redesigned. It's built as an HTML page styled like the app and printed to PDF by headless Chromium, which is already in the hosted image for screenshots (`backend/report_html.go`, `backend/reporttpl/report.html`).
  - **Cover:** the LLM Visibility Score as a ring, with the five dimension cards from the app's scorecard.
  - **Executive summary:** a scorecard page with a "Top 3 actions" box and key themes as cards.
  - **Sections:** each opens with its own score cards and a line on what each measures, and the overall LLM Visibility Score (the same number as the app, from one shared function) now appears in the report.
  - **Charts:** share of voice, LLM Test mention and recommendation rates, every optimized question ranked by score, and the sentiment split.
  - **Answer optimization:** detailed cards for the 10 weakest questions, the rest in an appendix.
  - **Recommendations:** cards by priority. Cross-channel actions are shown in full, plus the 15 most important answer fixes from the weakest questions; the rest stay with each question and in the To-Do list.
  - **Layout:** Inter typeface, page numbers, a clickable table of contents and PDF bookmarks. A real report went from 81 cramped pages of plain text to 39.
  - **Web version:** the same report opens as a web page from a new button next to the download (`GET /api/domains/{domain}/report/html`), and from public shares (`/api/share/{shareId}/report`).
  - **Fallbacks:** without Chromium, the PDF falls back to the plain report; `LLMOPT_CHROME_PATH` points at a browser. Cached PDFs record which engine made them, so existing reports regenerate in the new design.
- **Report**: fixed garbled characters such as "â€”" in the plain PDF (its built-in fonts are Windows-1252; text is now encoded for them rather than written as UTF-8) and fixed to-do summaries ending in "�" (text was cut in the middle of a character; truncation now cuts between characters).
- **Visibility score**: the YouTube, Reddit, Search and LLM Test parts of the score now use the same tenant scoping as everything else, so a server without SaaS sign-in counts them too.
- **Navigation**: the tab menu no longer scrolls sideways (with a hidden scrollbar), which hid the download button off the right edge. Everything fits on one row on laptop and desktop screens, and on narrower screens the menu wraps onto further rows instead of scrolling.
- **Optimize All**: fixed every question being counted as failed. The success check looked only at the last 4KB of each piece of the response, and a real result is a large block that follows the "done" line, so the marker was cut off. Optimizations were being saved all along; only the count and the summary were wrong.
- **Optimize All**: questions are optimized four at a time instead of one after another, so a domain with 50 questions finishes in roughly a quarter of the time. The button shows how many are done, running and failed, with a reminder to keep the tab open. A question counts as failed when its run ends in an error (these used to be skipped silently). A rate-limited one waits and goes back in the queue. When it finishes it says how many succeeded and failed, and clicking Optimize All again retries the rest.
- **Local account mode**: the local copy now answers only its own pages. It refuses requests addressed to any other host name (DNS rebinding) and requests from other sites (foreign `Origin` or `Sec-Fetch-Site: cross-site`), and it sends no CORS headers. Before this, any web page open in the same browser could call it and act as the account. `LLMOPT_LOCAL_ORIGINS` lists the address it's published at.
- **Hosting**: idle shutdown now sees LastSaaS traffic. Sign-in, billing, webhook and admin routes go through a small tracking proxy in llmopt (Caddy falls back to LastSaaS directly if it's down), so the machine never stops in the middle of one. Once shutdown is decided, new requests get a 503 (the page retries, which wakes the machine) instead of starting work that would be cut off. Only requests that passed authentication get the signed-in window; an `Authorization` header alone no longer does. Caddy caps the request bodies it buffers for llmopt at 5MB.
- **LLM Test**: an OpenAI rate limit no longer counts as a billing failure just because its message links to the billing page, which used to drop OpenAI from the whole run; the key check had the same mix-up. A Gemini 429 for depleted prepaid credits or billing now ends that key's use at once, instead of being retried as a per-minute limit for up to five minutes. Starting a test is no longer re-sent after a 504, which can come after the server has already started it.
- **LLM Test / saved queries**: an edit counts as saved only once the server confirms it. A failed save is retried with backoff and sent again when the page is hidden, with a note while it's pending. If a domain's saved list can't be loaded (after retries), the page says so with a Retry button and saves nothing until it loads, so the real list can't be overwritten. Queries typed while the list is still loading are kept, after the saved ones.
- **Reddit Authority**: a search Reddit refused is reported as the block even when the first search failed for another reason, so the OpenAI web-search fallback still runs. The fallback searches with your chosen subreddits as a hint. Threads found through web search no longer show a made-up date.
- **Repository**: `deploy.md` and `llmopt-mcp-wrapper.sh` no longer use one developer's absolute home-directory paths (the wrapper finds `mcp-remote` on `PATH`, as its own install note says); a test uses a placeholder name; `.claude/` is ignored.
- **Reddit Authority**: Reddit now refuses anonymous search requests ("You've been blocked by network security", HTTP 403) from servers and home connections alike, so Discover found nothing. Discovery now stops after two refused searches and, with an OpenAI key, finds the threads through OpenAI's web search limited to reddit.com instead (Anthropic's web search can't reach Reddit). Searches run four topics per request, three requests at a time. Only threads whose URL is among the search's own sources are kept, and each carries a summary, reply excerpts and the names discussed into the analysis, which is told that upvotes and comment counts are unknown for them. Such threads show "via web search" in the list. Without an OpenAI key, the page says Reddit blocked the search and how to fix it. Errors used to vanish because the page went straight back to the settings view; the last Discover error now stays under the button. If every search fails for another reason, that error is shown instead of "no threads found".
- **LLM Test**: when a provider's first model went silent, a query whose call was still waiting could be marked failed after another query had already switched to the next model and answered there; it now retries on the new model.
- **YouTube**: in local account mode, a copy with its own `YOUTUBE_API_KEY` uses it for YouTube instead of the account's saved key, and the provider status doesn't report the saved key's state. A used-up YouTube quota is reported in plain words (when Google resets it) instead of Google's raw error.
- **Local account mode**: with `LLMOPT_LOCAL_USER_ID` and `LLMOPT_LOCAL_TENANT_ID` set, the app runs on your own machine against the hosted service's database as that account, with its domains, reports and saved API keys, and without LastSaaS or signing in. It's meant for work the hosted server can't do well, such as YouTube transcripts, which YouTube blocks from datacenter addresses. It listens on loopback only (`LLMOPT_LISTEN_HOST` must be a loopback address) and runs no migrations or background jobs. The UI runs as single-user.
- **Reddit Authority**: fixed the input view being unusable. The tab's setup effect refetched the analyses list, and the list was one of its own dependencies, so it ran in an endless loop: hundreds of requests a second for the list and the brand profile. Each pass refilled the settings from the brand profile, so Settings closed as soon as it opened and added search terms vanished. A domain with a saved report kept being sent back to it, so "Re-run or Change Settings" did nothing. The settings are now filled from the brand profile once per domain, and a saved report opens once. Switching domains no longer carries the previous domain's subreddits over. When Discover is disabled because there are no search terms, the page now says so.
- **LLM Test**: each provider now answers in its own lanes (two queries at a time) instead of sharing six slots with the others. A provider whose calls hang or wait on a rate limit used to fill the shared slots and hold up every other provider's queries; now it holds up only its own.
- **LLM Test**: a model that hasn't answered anything yet in a run and then times out (no reply within the 3-minute request limit) or stays over the key's rate limit is left for the provider's next model, with a note saying why, instead of failing query after query for minutes. Up to six model switches per run (was three), since a free key can't use several of the models listed first.
- **LLM Test**: a per-minute rate limit pauses all of that provider's queries for as long as the provider asks (Gemini's retry hint), with a note quoting the provider's message, instead of each query retrying on its own. A query is retried up to four times on a rate limit; after five minutes of waiting on one provider in a run, its remaining queries are skipped so the run still finishes. A call that takes over 75 seconds says the provider is slow. Failed provider calls are logged on the server.
- **LLM Test / Gemini**: the default model is now Gemini 4 Hydrogen, the model the free Gemini app answers with and the only Gemini 4 model on the API's free tier. Keys that don't list it keep the newest stable Flash.
- **Brand profile**: list fields (products, categories, use cases, differentiators) no longer split at commas inside brackets, which turned "Starter Kit (monthly plan, 50 seats)" into "Starter Kit (monthly plan" and "50 seats)" and produced broken suggested test questions. Lists already saved that way are rejoined when the profile is saved and when test questions are suggested.
- **LLM Test / Gemini**: a Gemini 429 is read instead of treated as "overloaded". When a model has no quota for the key (Google's free tier allows no requests to some Pro models, or the day's quota is used up) the run moves to the next model; a per-minute limit waits as long as Google asks (up to 60s) before retrying. The reason shown when Gemini can't answer now includes Google's message. A quota 429 no longer marks a Gemini key "out of credits"; only depleted prepaid credits or billing do.
- **LLM Test / Gemini**: the default model is now the newest stable Flash, the model family the Gemini app answers with, instead of the top Pro model. Other models can still be picked.
- **LLM Test / Claude**: answers from Claude 5-generation models (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable, Mythos) came back empty. These models think before answering and return thinking blocks ahead of the text, and the response reader took only the first block. It now joins all text blocks, adds output headroom for the thinking (as for the other providers' reasoning models), and reports a refusal or an answer cut off by the budget as a failure. Any blank answer from any provider now counts as a failed query instead of being scored as "brand not mentioned".
- **LLM Test / OpenAI**: the default model is now `chat-latest`, OpenAI's alias for the model ChatGPT's Chat tab answers with, instead of the newest API model (frontier models such as GPT-6.1 Terra aren't served in ChatGPT's chat). Without the alias, the newest `*-chat-latest` model is used. Other models can still be picked; the picker says why its default was chosen. The evaluation step still uses the best model.
- **LLM Test**: test queries are saved per domain (`GET`/`PUT /api/test/{domain}/queries`, collection `test_query_sets`) shortly after each edit, when the page is hidden, and when a test starts, so they are there again after leaving the page. Before anything is saved, a domain shows its latest test's queries; suggestions are generated only for a domain that has never had any. "Re-run Test" (and "Re-run or Change Settings") on a results page starts from exactly the queries shown in those results.
- **Hosting**: the machine now decides when to stop instead of Fly's proxy, which stopped it after a few idle minutes, sometimes mid-way through someone's work. With `LLMOPT_IDLE_SHUTDOWN=60m` (set in `fly.saas.toml`), it stays up until 60 minutes pass without a signed-in request (`LLMOPT_IDLE_SHUTDOWN_VISITOR`, 10 minutes, for anonymous visits and for the boot itself), never stops while a request is in flight, and ignores the health polls open tabs send every 5 minutes. It then asks supervisord to shut down; the machine stops cleanly (restart policy `on-failure`), and Fly's proxy starts it on the next request. `auto_stop_machines` is now `off`.

## 2026-11-13

- **LLM Test**: a provider that can't be used no longer stops the test. Providers without a key are skipped with a note. A provider whose key is rejected or out of credit is dropped after its first failure, and the rest of its queries are skipped. Rate-limit and overload errors are retried with backoff. A retired model makes the run switch to the provider's next model. Providers that answered nothing are listed in a new `unavailable_providers` field (shown on the results page and in the PDF) instead of counting as zero in the overall score. Per-provider rates are now computed over the queries that provider answered (`answered`/`failed`).
- **LLM Test**: the evaluation step falls back to another provider that just answered when the primary provider can't evaluate, and reads evaluator output wrapped in prose or code fences.
- **Models**: the model list for each provider is now fetched live from the provider (Anthropic, OpenAI, Gemini, xAI `models` endpoints) for the tenant's own key, cached for 6 hours, and ranked best first. The LLM Test defaults to the best available model. The built-in lists remain as a fallback.
- **API keys**: key checks list the provider's models first and test with the cheapest current one, so a retired model no longer makes a valid key look broken. The LLM Test page shows keys whose last check failed, with a Re-check button, instead of hiding them.
- **OpenAI**: requests to the Responses API now send `input` and `max_output_tokens` (they were sending the Chat Completions `messages`/`max_tokens` fields). Reasoning models (GPT-5, o-series), Gemini 2.5+ thinking models and Grok reasoning models get extra output budget so their reasoning doesn't use up the answer. Exhausted OpenAI quota is reported as a billing problem, not as an overload.
- **Gemini**: the API key is sent in the `x-goog-api-key` header instead of the URL, so it can't appear in error text. Multi-part answers are joined.
- **Cold starts**: Caddy now holds requests for up to 45s while the backends start (`lb_try_duration`), and buffers llmopt request bodies so a POST that arrives during startup is replayed instead of failing with 502. WARP connects in the background so the app starts immediately, and the WARP check is retried instead of being cached as unavailable. The frontend retries a test start on 502/503/504 with a "waking up" note, and explains other failures (rate limit, expired session) instead of showing "Failed to start test".
- **LLM Test**: fixed the model picker being ignored (stale `testModelSelections` in the run callback).

## 2026-06-18

- **LLM Test**: added a periodic SSE heartbeat to all 15 streaming endpoints, keeping the connection alive through long, silent LLM calls. Fixes the "Load Failed" error that dropped the Test stream mid-run behind the production proxy chain (Fly edge -> Caddy).
- **LLM Test**: Phase 1 provider queries now run concurrently (capped at 6) instead of sequentially, cutting a large provider×query matrix from the sum of all calls to roughly the slowest single call. The overall request timeout was raised from 5 to 15 minutes. Together these fix the "Could not resolve primary LLM for evaluation" error that occurred when a long run exhausted the request budget before the evaluation step.
- **API keys**: `resolveProviderKey`/`resolvePrimaryLLM` no longer map transient DB/context errors to `api_key_required`; a genuinely-missing key returns a sentinel error while real failures are wrapped and logged. The Test evaluation also falls back to a tested provider's key when the primary provider has none configured.
- **Report**: the aggregate PDF's "YouTube Video Authority" section now renders the brand narrative ("What LLMs Probably Believe About You") with sentiment, key themes, share of voice, content-gap opportunities, top creators, creator outreach targets, and the confidence note — matching the YouTube tab instead of showing only scores and scorecard titles.

## 2026-06-05

- **Video Authority**: added warning banner explaining that YouTube's bot detection frequently blocks transcript fetching from datacenter IPs (including the hosted instance at llmopt.fly.dev), and recommending self-hosting on a residential connection for reliable results.

## 2026-06-03

- **Video Authority**: added `yt-dlp` + `deno` based transcript-fetcher as the primary method, with the existing InnerTube clients (TVHTML5 embed, MWEB, WEB, ANDROID, watch-page scrape) retained as fallbacks. yt-dlp's EJS challenge solver is enabled via `--remote-components ejs:github` so the JS-challenge step succeeds when the egress IP is residential.
- **Video Authority**: sticky preference cache for transcript methods — once a method succeeds it floats to the front of the list for subsequent calls in the same process.
- **Video Discovery**: added opt-out checkbox for auto-generated brand-name search queries (`<brand> review`, `<brand> tutorial`, `<brand> vs <competitor>`) to avoid false positives when the brand name is a common phrase.
- **Video Discovery**: errors from individual YouTube search calls are now surfaced via the progress stream and logged, instead of being silently swallowed.
- **Rate limiting**: keyed by `(client IP, request path)` so per-endpoint limits don't share a counter. `VideoDiscoverLimit` and `VideoAnalyzeLimit` bumped from 3/min to 10/min.
